## 一、拓扑

```
                     外部访问者（面试官 / 你自己）
                            │
                            ▼  HTTPS/HTTP
                    ┌───────────────┐
                    │  cpolar 隧道   │  ★ 只转发一个端口：80
                    └───────┬───────┘
                            │
   ═════════════════════════▼══════════════════════════ 宿主机
                    ┌───────────────┐
                    │  nginx :80    │  ★★ Basic Auth 在这里
                    │               │  ★★ SSE 的 proxy_buffering off 在这里
                    └───┬───────┬───┘
              /api/*    │       │    /*
                        ▼       ▼
        ┌───────────────────┐  ┌──────────────────────────┐
        │  app :8080        │  │  Vue 构建产物（静态文件）  │
        │  Spring Boot      │  │  + /docs/ 两张白名单报告   │
        │  ★ 不映射到宿主机  │  └──────────────────────────┘
        └───┬──────────┬────┘
            ▼          ▼
     ┌──────────┐  ┌────────┐
     │ postgres │  │ redis  │   ★ 只绑 127.0.0.1，公网够不到
     └──────────┘  └────────┘
```

★ **两条红线**（`docs/02` §29）：

```
① 隧道只指向 nginx 的 80 —— 5432 / 6379 / 5050 按构造就够不到
② 数据库端口只绑 127.0.0.1 —— 连同一局域网的其他机器都连不上
```

## 二、两条路，别混

这个项目**同时**有两套运行方式，它们是刻意并存的：

| | 本地开发 | 容器全栈 |
|---|---|---|
| 命令 | `docker compose up -d` + `./mvnw spring-boot:run` | `docker compose --profile full up -d` |
| 起什么 | 只有中间件 | 中间件 + 应用 + Nginx |
| 应用在哪 | 宿主机，端口 **8080** | 容器里，**不映射端口** |
| profile | `local` | `prod` |
| 用途 | 跑测试、跑探针、改代码 | 部署演示、给人访问 |
| 密钥来自 | `application-local.yml` | 环境变量（`.env`） |

★★ **为什么必须并存**：阶段 7 的 `scripts/eval_run.py`、`probe_*.py`、
以及 `./mvnw clean test`（860 个用例）**全部假设 `localhost:8080`** 和
宿主机上的 postgres/redis。把本地那条路弄断，等于把整条「可复现」的链弄断 ——
而那正是这个项目最值钱的部分。

★ 做法上靠两点保证：**应用容器不映射 8080**（宿主机那个端口留给 `mvnw`），
以及 **`app`/`nginx` 挂在 compose profile 上**（默认 `up -d` 行为一字不变）。

## 三、一次性准备

### 3.1 `.env`

```bash
cp .env.example .env
# 然后填 4 个值（★ 这个文件在 .gitignore 里，不会被提交）
```

| 变量 | 什么时候需要 |
|---|---|
| `POSTGRES_PASSWORD` | **总是**（中间件就要） |
| `PGADMIN_PASSWORD` | **总是** |
| `PGADMIN_EMAIL` | 有默认值，可不填 |
| `DEEPSEEK_API_KEY` | ★ 只有 `--profile full` 才需要 |
| `SILICONFLOW_API_KEY` | ★ 同上 |

⚠️ **模型密钥在这里是第二份拷贝**（第一份在 `application-local.yml`）。
这是唯一一处密钥重复，代价很具体：**换了 key 要两处都改** ——
只改一处时本地开发是好的、容器里报 401，而那句 401 不会告诉你改漏了哪个文件。

★ 为什么不能让容器读 `application-local.yml`：那个文件在 `.dockerignore` 里
（密钥不该进镜像层），而且 `prod` profile 下 Spring 根本不会加载它
（**profile 是替换不是追加**，见 `docs/10` 坑 10）。

### 3.2 Basic Auth 口令

```bash
bash deploy/make-htpasswd.sh          # 交互式输入口令
```

产物 `deploy/.htpasswd` **在 `.gitignore` 里** —— 它是凭据，
而 Basic Auth 是公网这一版**唯一**的访问控制手段。

⚠️ 实测（2026-09-24，Windows）：脚本里的 `umask 077` 在 NTFS 上**不生效**，
产物是 644 而不是 600。真正起作用的保护是 `.gitignore` 那一条。
在 Linux/macOS 上 umask 正常。

## 四、起服务

### 4.1 容器全栈

```bash
docker compose --profile full up -d --build
docker compose --profile full ps
```

★ **`--profile full` 不能省**。省了只起中间件 ——
而那不是「错了」，那正是本地开发要的样子（见第二节）。

### 4.2 ★★★ 灌数据（**两步，顺序不能反**）

> ⚠️ **干净环境的库是【全空】的。** Flyway 只建表结构，一行数据都不灌。
> 2026-09-24 用一个空卷起全栈逐表 count 实测：
>
> ```
>   产品 0 · 订单 0 · 券 0 · 知识库文档 0 · 知识库切片 0
>   评测题 0 · qa_log 0 · 会话 0
> ```
>
> ★ `SeedRunner` 挂在 **`@Profile("seed")`** 上 —— 一个**专门的开关**，
> 不是 `local`。所以 `prod` profile 下它**根本不跑**（这是有意的：
> 灌数据不该是每次启动的副作用）。

```bash
# ① 业务数据（商品 200 / SKU 578 / 库存 578 / 券 8 模板 71 张 / 订单 120 / 售后政策 12）
bash scripts/seed.sh

# ② 知识库（要调向量化 —— 这是【唯一】会花钱的手工步骤）
python scripts/ingest.py --url http://localhost -u xbla:<口令>
```

⚠️ **顺序不能反**：知识库的「业务表 → 文档」那一步
（`POST /api/kb/documents/sync`）读的正是 ① 灌进去的商品和售后政策。
**先灌知识库的话会同步到 0 份，而且不报错。**

★ **为什么两步都不做成自动的**：

```
① business 数据  做了自动 → 每次启动都灌一遍；虽然幂等，但「起容器」
                            顺手改数据库不该是默认行为
② 知识库         做了自动 → 每次 up -d 都【静默产生外部调用】
                            —— 一个起容器的动作不该花别人的钱，
                               也不该在离线的机器上失败
```

⚠️ 都灌完之后会怎样（这个失败形态很隐蔽）：问答**照样能跑**、
HTTP 200、有回答 —— 因为检索为空会退化成裸聊，而**裸聊会编一个订单状态出来**。
所以它排在验收清单里，判据不是「有没有报错」而是「引用列表空不空」。

## 五、验收清单（★ 2026-09-24 已全部实测通过）

> ★ 每一条都要**看到那个输出**，不是「应该没问题」。
> 沿用阶段 6/7 的纪律：**留命令 + 输出，不留印象。**
>
> ⚠️ **下面这些命令必须打【公网那一侧】**（cpolar 给的地址）。
> 打 localhost 验的是「Nginx 在不在」，不是「外面的人看到什么」——
> 而这两者之间隔着隧道，隧道也有它自己的行为。

### A. 安全（★ 这三条是「不通过就得回滚」的级别）

```bash
# ① 调试探针在公网上必须 404
#    ★ 若这条挂了，7 个 @Profile("local") 控制器全部可用 ——
#      其中 POST /api/debug/ratelimit/leak 能改状态，
#      /api/debug/llm/chat 能无条件烧你的 API 额度。
curl -s -o /dev/null -w '%{http_code}\n' -u u:p http://<地址>/api/debug/ratelimit/state

# ② 简历讲稿必须 404（docs/00 不进公开仓库，而 docker 不认 .git/info/exclude）
curl -s -o /dev/null -w '%{http_code}\n' -u u:p "http://<地址>/docs/00-项目总览.md"

# ③ 数据库和 Redis 从外面连不上
nc -zv <地址> 5432
nc -zv <地址> 6379
```

**实测（2026-09-24，容器全栈走 Nginx）**：

```
① /api/debug/ratelimit/state      → 404  ✓
   /api/debug/llm/chat            → 404  ✓
   /api/debug/kb/search-text-stats→ 404  ✓
② /docs/00-项目总览.md            → 404  ✓  ★ 简历讲稿没出去
③ 5432 / 6379 只绑 127.0.0.1（docker compose config 确认 host_ip）
```

★★ **① 第一次测的时候是 500，不是 404** —— 那暴露了一个真 bug：
Spring Boot 3.2 起，未匹配的路径抛 `NoResourceFoundException`，
而 `GlobalExceptionHandler` 的兜底 `@ExceptionHandler(Exception.class)` 把它接走 → 500。
**这个应用里每一个 404 都被渲染成了 500**，而它是阶段 8 之前就存在的。
修法与测试见 `docs/10` 坑 30 / `UnmappedPathMappingTest`。

## 六、★ 开隧道【之前】必须先核的：暴露面审计（2026-09-26）

> ★★★ **为什么这一节单独存在**
>
> `cpolar http 80` 是一条命令、**10 分钟**。
> 而「开它 = 把服务暴露到公网」是一个**外向动作**。
> 两者的成本差两个数量级，**而只有后者需要想清楚**。
>
> ★ 所以这一节的每一条都是**打出来的**，不是读配置读出来的 ——
> 因为这个项目已经栽过一次「读配置觉得没问题，实测是 500」（见 §五 那条 ★★）。

### 6.1 哪一面会被暴露：只有 Nginx

```bash
docker compose ps --format "table {{.Service}}\t{{.Ports}}"
```

```
app        8080/tcp                       ← ★ 【没有】映射到宿主机
nginx      0.0.0.0:80->80/tcp             ← ★ 唯一对外的一面
pgadmin    127.0.0.1:5050->80/tcp
postgres   127.0.0.1:5432->5432/tcp
redis      127.0.0.1:6379->6379/tcp
```

★★ `cpolar http 80` 只转发 80，所以**隧道能碰到的只有 Nginx 那一层**。
应用容器不发布端口这件事，在这里挣回了它的价值：
**「不小心把应用直接暴露出去」变成一个连不上，而不是一个静默的泄露**（§二）。

### 6.2 实测：生产下真的存在哪些端点

七个 `@Profile("local")` 的控制器**全部 404**（逐个打出来的）：

```
/api/debug/kb/search-text-stats   → 404     /api/debug/eval/config      → 404
/api/debug/agent/intent-tree      → 404     /api/debug/profile/affinity → 404
/api/debug/mcp/tools              → 404     /api/debug/llm/chat         → 404
/api/debug/ratelimit/state        → 404
```

actuator 白名单也生效（`include: health,info,circuitbreakers,circuitbreakerevents`）：

```
/actuator/health          → 200     /actuator/env    → 404   ★ 没泄露配置
/actuator/info            → 200     /actuator/beans  → 404
/actuator/circuitbreakers → 200
```

**而生产下真的存在的是这些**（剩下 8 个控制器）：

| 方法 | 路径 | 性质 |
|---|---|---|
| POST | `/api/chat`、`/api/chat/stream` | ★ **写 + 花钱**（每次 ≈ **0.0009 元**，实测 166 次 / 0.3154 元） |
| GET | `/api/chat/stream` | 花钱 |
| GET | `/api/chat/sessions`、`/messages`、`/trace/{id}`、`/refs/{t}/{c}` | 只读 |
| POST | `/api/events` | ★ 写（免费，9.6b 刻意接受的） |
| POST | `/api/kb/documents`、`/scan`、`/sync` | ★★ **写知识库** |
| GET | `/api/kb/documents/{id}` | 只读 |
| POST | `/mcp` | ★ 工具直调（⚠️ **隧道到不了**，见下） |
| GET | `/api/status/ratelimit`、`/api/status/metrics`、`/api/health` | 只读 |

★ **`/mcp` 从隧道到不了**：Nginx 只配了 `/api/`、`/docs/`、`/assets/`、`/` 四个 location，
`/mcp` 会掉进 `location /` 的 `try_files` → 返回 `index.html`。
（⚠️ 这一条是**按配置推导**的，没实测 —— 需要口令才能区分 401 与 index.html。
影响低：它本来也在 Basic Auth 后面。）

### 6.3 ★★★ 审计发现的五条

#### E1 · `X-Xbla-User-Id` 可编 ⇒ **读任意用户的订单与券**

```
initialize 时各用一个新会话：
  X-Xbla-User-Id: 8  → 「你有 1 张可用的优惠券：家电品类满 8000 减 800…」
  X-Xbla-User-Id: 5  → 「你有 2 张可用的优惠券：全场满 3000 减 400…」
  X-Xbla-User-Id: 12 → 「你有 1 张可用的优惠券：家电品类满 8000 减 800…」
```

★ `ADR-054` 早就写着「`X-Xbla-User-Id` 不是认证」，**但那时候没有公网入口**。
⇒ **同一个事实，在「只有本机能访问」和「挂了隧道」两种情况下量级完全不同。**

⚠️ **减轻了一点**：`/mcp` 会把身份**绑在会话上**，同一会话里换头会被拒
（`会话身份与请求头不一致`）—— 但换个头值**重开一个会话**就绕过了。
★★ **没有减轻的是 `/api/chat`**：它同样吃这个头，而它在隧道的可达范围里。

#### E2 · `POST /api/kb/documents` ⇒ **知识库投毒**

上传一份文档就会触发切分 + 向量化 + 入索引，**RAG 之后会引用它**。

★★★ 这一条比「花钱」严重得多，而且它**正好打在这个项目的卖点上**：
本项目说「引用列表是能区分『从知识库来的』和『编的』的最便宜的证据」——
而一份被灌进去的文档会产生**带着引用的、看起来完全合法的回答**。

#### E3 / E4 · 还有两个 Spring 异常被兜底吞成 500　【★ 已修 2026-09-26】

```
GET  /api/events                     → 500   应该 405   ← HttpRequestMethodNotSupportedException
GET  /api/chat/sessions?limit=abc    → 500   应该 400   ← MethodArgumentTypeMismatchException
```

★ 这是 `docs/10` 坑 30 那个家族的**第三、四个实例**：
坑 30 修了 404，2026-09-26 修了 400/415（坑 54），**这两个是那次审计剩下的**。
症状同前：客户端错误被报成服务故障，**监控按 500 计数时会告警**。

**修法**：两条 handler（405 + 400）。★ 405 按 RFC 9110 §15.5.6 **带 `Allow` 头**
（缺了它调用方只能猜「到底该用什么方法」）；
400 的消息里回**参数名**、**不回客户端传的那个值** ——
原样回进 body 就是一次反射式内容注入。

**实测（2026-09-26，本地 8080 跑新代码）**：

```
GET    /api/chat                    → 405    Allow: POST          ✓
GET    /api/events                  → 405                          ✓
DELETE /api/status/ratelimit        → 405                          ✓
GET    /api/chat/sessions?limit=abc → 400   「参数 limit 的格式不对」 ✓
GET    ...sessions?limit=<script>   → 400   消息里【没有】script     ✓
GET    ...sessions?limit=1          → 200   ★ 反例：不是「什么都 400」✓
```

★ **变异验证**：摘掉那两条 `@ExceptionHandler` → **4 条用例全红**
（`expected:<400>/<405> but was:<500>`），第 5 条正例仍绿；还原后 10/10 绿。

★ 对照组（**这三个本来就是对的**，说明不是「什么都 500」）：

```
Accept: application/xml                 → 406  ✓
POST /api/chat  体是 []（不是对象）      → 400  ✓
POST /api/kb/documents  非 multipart    → 415  ✓
```

⚠️ **容器里那个镜像还没重建** —— 上面这些是本地 8080 实测的。
要公网生效得 `docker compose --profile full up -d --build`。

#### E5 · ★★ **和隧道无关**：本地开发实例裸奔

```
netstat -ano | grep LISTENING
  0.0.0.0:8080   ← ★ 我起的 mvnw spring-boot:run，绑【所有网卡】
  0.0.0.0:80     ← nginx（有 Basic Auth）
  127.0.0.1:5432 / :6379 / :5050   ← 只本机 ✓
```

从本机局域网 IP 打过去：

```
http://172.22.48.1:8080/api/debug/ratelimit/state  → 200   ★ 无认证
http://172.22.48.1:8080/api/debug/mcp/tools        → 200   ★ 无认证
```

★★★ `auth_basic` 是 **Nginx 的**，8080 上的应用**裸着**，
而它跑的是 `local` profile —— **7 个 debug 控制器全在**，
其中 `/api/debug/llm/chat` **能无条件烧你的 API 额度**（`ADR-087` 担心的正是这件事）。

⚠️ **只要你在共享网络里（宿舍网、公司网、咖啡馆）跑过 `./mvnw spring-boot:run`，
同一网段的人就能打到它。** 而这件事和开不开隧道**完全没有关系**。

**缓解**（任选）：跑开发实例时绑回环 ——
`./mvnw spring-boot:run -Dspring-boot.run.arguments=--server.address=127.0.0.1`。

### 6.4 开隧道前的检查清单

★★★ **先跑这条命令**，别照着单子抄 —— 判据在代码里，不在记忆里：

```bash
# 打 Nginx 那一侧（有 Basic Auth，所以必须带 -u）
python scripts/probe_exposure.py --url http://localhost -u 用户:口令
# 隧道开起来之后，打公网那一侧：
python scripts/probe_exposure.py --url https://xxx.cpolar.cn -u 用户:口令
```

★ 它验的东西全部**不花钱、不写库、不改状态**（不调模型、不上传、不 scan/sync/发埋点）。
「验一个端点存不存在却不执行它」靠的是**发一个错的 HTTP 方法** ——
这个手法本身就是 §6.3 E3/E4 的发现方式。

★★ 它的输出分两类，**别混着读**：

```
  ✅/❌   判据 —— 有对错，❌ 就该当场处理
  📌     已知边界 —— 【不判对错】。把 §6.3 那几条的证据重新摆一遍，
                 让你在开隧道前再确认一次「我接受这些」
```

★ 第二类不是凑数：一个只报「通过」的探针会让人以为「没问题」，
而实际是**「有几个已知的问题，我选择接受」**。

⚠️ **打开发实例（:8080）时它会在【1】报红，那是正常的** ——
它跑 `local` profile，七个 debug 端点本来就在。脚本开头会把这句话打在屏幕上。
★ 同理【2】/【4】在那一侧会显示「⏭ 不适用」而不是失败：
**假失败会训练人忽略失败**，而这几节的价值就是「真失败时你会当场停下来」。

**机器判不了的四条，仍需你自己确认**：

```
□ 口令是【强口令】，而且没有发给过不该发的人 —— 它是【唯一】的访问控制
□ 清楚 E1：拿到口令的人能读任意用户的订单/券
□ 清楚 E2：拿到口令的人能往知识库灌内容
□ 演示结束后真的把隧道关掉 —— 关客户端一条命令的事
```

⚠️ 另外两条**在跑探针之前**就该确认：

```
□ E3 / E4 已修（✅ 2026-09-26）—— ★ 但**容器镜像要重建过**才算数
   （改的是 Java 代码，`up -d --build` 之前的镜像里没有那两条 handler）
□ 开发实例（8080）没在同时跑着，或者已经把它绑回环（E5）
```

## 七、内网穿透（cpolar）

```bash
cpolar http 80        # ★ 指向 Nginx 的 80，不是应用的 8080
```

★★★ **先看 §六。** 那个审计是**开隧道之前**要做的，
而这一节只是「隧道本身怎么开」。

⚠️ 免费版的已知边界：

```
① ★★ 地址是【随机二级域名】，而且约【24 小时轮换一次】——
   不能自定义，重启客户端也会换。⇒ 别把它写进任何文档/简历/聊天记录
② 带宽 1Mbps（≈128KB/s）—— 那张 1.1MB 的前端 bundle 首次加载约 10 秒
③ 一个账号同一时间只能有一个在线进程；依赖第三方，对方挂了你就访问不了
④ 只有共享证书；「隧道入口到 cpolar」那一段是 https，
   「cpolar 到你本机」那一段是明文（同 §十 ④）
```

★★ **这四条合起来改变了一件事的份量**：地址是临时的、24 小时失效的。
⇒ 「我挂了个公网地址」这件事**本身就是一次性的**，
而「我把它部署起来了」是持久的（那是 §五 验收清单管的事）。
**两者别混着说。**

★ **为什么指向 80 而不是 8080**：8080 是应用的端口，而应用容器
**根本没有映射到宿主机**（第二节）。指向它连不上 —— 这是有意的，
它让「不小心把应用直接暴露出去」变成一个连不上、而不是一个静默的泄露。

## 八、日志

两层，各自管各自的：

| 层 | 在哪 | 看什么 |
|---|---|---|
| 应用日志 | 命名卷 `app_logs` → `/var/log/xbla/app.log` | ★ 问答链路细节、名额、降级 |
| 容器 stdout | `docker compose logs` | 启动失败、健康检查 |

```bash
docker compose --profile full exec app tail -f /var/log/xbla/app.log
docker compose --profile full logs -f --tail=100 app
```

★ **两层都限了大小**：

```
应用侧    application-prod.yml 的 logging.logback.rollingpolicy
容器侧    docker-compose.yml 的 x-logging 锚点（json-file 10MB × 3）
```

⚠️ 只配一层不够：应用侧管的是**容器内那个文件**，容器侧管的是
**docker 收集的 stdout**。漏掉容器那层的话，日志会一直长到把磁盘写满 ——
而磁盘满的症状是「所有写操作都失败」，看起来像数据库坏了。

★ 要看更细的日志（比如阶段 6 的名额问题），**不用改文件**：

```bash
LOGGING_LEVEL_COM_XBLA_RAG=debug docker compose --profile full up -d app
```

## 九、常见故障

| 现象 | 成因 | 怎么确认 |
|---|---|---|
| 前端加载了但接口全 404 | Nginx 的 `location /api/` 没配，或者应用容器没起来 | `docker compose --profile full ps` |
| ★ 答案等 30 秒一次性全出现 | `proxy_buffering` 没关 | 看 `deploy/nginx.conf` 里 `location = /api/chat/stream` |
| 首页正常，一刷新就 404 | SPA 的 `try_files ... /index.html` 没配 | 同上，`location /` |
| 容器起来了但报 401（模型侧） | 密钥改了但只改了 `application-local.yml` | 对照 `.env` 里那两份 |
| `/docs/` 下报告 404 | 那个文件不在 `Dockerfile.web` 的 COPY 列表里 | 白名单是**显式**的，加文档要改那一行 |
| 应用容器起不来，报「必须提供 DEEPSEEK_API_KEY」 | `.env` 里没填 | ★ 这是**有意的**：宁可启动失败，也不要跑起来之后第一次提问才炸 |
| 5432 连不上（本机可以，别的机器不行） | ★ 这是**对的** —— 端口只绑 127.0.0.1 | `docker compose config \| grep host_ip` |

## 十、已知边界

```
① 单实例。Nginx 上面没有负载均衡，应用只有一份。
   阶段 6 的排队限流用的是 Redis，本来就支持多实例 —— 但【没验过】多实例。

② ★★★ **Basic Auth 是【唯一】的访问控制，而它【只保护 Nginx 那一面】。**
   它挡得住扫描器，挡不住「知道口令的人把地址转发出去」。
   ★ 而且**拿到了口令就等于拿到了所有人**：
   `X-Xbla-User-Id` 是明文未签名的（ADR-054），改一个头值就能读
   任意用户的订单与券 —— 实测见 §六 E1。
   ⇒ 一个共享口令的站，**不分你我**。没有用户体系、没有配额。
   ⚠️ 且 `auth_basic` 是 Nginx 的：**8080 上的开发实例是裸的**（§六 E5）。

③ 令牌不算小：前端 bundle 约 1.1MB（gzip 后 359KB），
   其中绝大部分是 Element Plus。隧道有带宽限制时首次加载会明显慢。

④ 没有 HTTPS。cpolar 免费版给的地址是 https，但那是「隧道入口到 cpolar」
   那一段；「cpolar 到你本机」这一段是明文。演示数据不含个人信息，
   这个取舍是清楚的。

⑤ ★【未验】多实例部署、HTTPS 终止、镜像推送到 registry —— 本阶段都没做。
   写在这里是为了让「没做」和「做了但没写」能被区分开。

⑥ ★★ **知识库是【可写】的**（`POST /api/kb/documents` 上传即入库）。
   灌进去的文档会被切分、向量化、进索引，**然后 RAG 会引用它**。
   ⇒ 而本项目的卖点正是「引用是能区分『从知识库来的』和『编的』的证据」——
   **一份被灌进去的文档会产生带着引用的、看起来完全合法的回答**（§六 E2）。
   ⚠️ 演示完关隧道之前，先确认知识库里没有多出不该有的文档。

⑦ ★★ **跑开发实例（`./mvnw spring-boot:run`）时，它就是裸的。**
   Spring Boot 默认绑 `0.0.0.0`，而 `auth_basic` 是 Nginx 的、不在它身上；
   它跑的又是 `local` profile ⇒ **7 个 debug 控制器全部可达**，
   其中 `/api/debug/llm/chat` **能无条件烧 API 额度**（§六 E5）。
   ⇒ 共享网络里跑它，请加 `--server.address=127.0.0.1`。

⑧ **每次问答 ≈ 0.0009 元**（实测 166 次 / 0.3154 元）。
   单次可以忽略，但它是**无配额**的：拿到口令的人狂刷 1 万次 ≈ 9 元。
   ★ 而「被刷」和「有人在做压力测试」在账本上长得一模一样 ——
   只能靠 §八 的访问日志去分。
```
